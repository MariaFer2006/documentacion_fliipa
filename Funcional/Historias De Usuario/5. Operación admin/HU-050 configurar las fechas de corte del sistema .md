#### HU-050: Configurar las fechas de corte del sistema

| Campo | Detalle |
|:---:|:---:|
| **Actor** | Administrador con permiso de edición de configuración (rol Sys Admin o Core Admin con el permiso "Editar configuración"); cualquier administrador autenticado puede consultar las fechas de corte vigentes en modo solo lectura. |
| **Historia** | Como administrador con permiso de edición de configuración, quiero consultar y editar los días de corte válidos, el día de corte por defecto y el umbral de días usados para asignarlos, para poder ajustar el ciclo de facturación del crédito sin necesidad de un despliegue de código. |
| **Prioridad** | Alta |
| **Criterios de aceptación** | Cualquier administrador con sesión activa puede ver el valor actual del setting `cutoff_dates` (`cutoffDates`: lista de días de corte válidos, `defaultCutoffDate`: día de corte por defecto, `thresholdDays`: umbral de días), junto con la fecha de su última actualización. Solo un administrador con el permiso "Editar configuración" puede modificar estos valores; si no lo tiene, el campo se muestra en modo solo lectura. Al guardar, el sistema valida que el texto ingresado sea JSON válido antes de enviarlo al backend. El sistema rechaza la actualización si el nombre del setting no existe o si no se envía un valor. Toda actualización exitosa o fallida queda registrada en el log de auditoría del panel. |

| **Comentarios** | **Historia nueva, implementada.** No existía ninguna historia que documentara la edición de las fechas de corte del sistema desde el panel admin. Se separa de la tasa de interés y del resto de parámetros técnicos (ver HU-049 y HU-051) porque define el ciclo de facturación de todos los créditos y amerita seguimiento propio. **Hallazgo técnico:** igual que con la tasa de interés, la ruta `PUT /settings/:name` solo exige `authenticate` en el backend, sin validar el permiso `core:update-setting` a nivel de API. **Hallazgo adicional:** el tipo `THRESHOLD_DAYS_SETTING_NAME` (`threshold_days`) está declarado en `settings.types.ts` como si fuera un setting independiente, pero no se siembra ni se usa por separado; el valor `thresholdDays` que sí está activo vive anidado dentro de este mismo setting `cutoff_dates`. Se recomienda limpiar la constante no usada o documentar su propósito real. |
