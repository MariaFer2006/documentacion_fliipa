#### HU-050: Ver, crear e importar bonos D1 para clientes

| Campo | Detalle |
|:---:|:---:|
| **Actor** | Administrador del producto |
| **Historia** | Como administrador del producto, quiero listar, crear individualmente e importar de forma masiva bonos (cupones) D1 vinculados a clientes existentes, y consultar el detalle de cada bono con sus compras asociadas, para poder asignar cupo adicional de compra en tienda D1 a los clientes que negocio autorice. |
| **Prioridad** | Media |
| **Criterios de aceptación** | El administrador puede listar los bonos D1 con paginación, búsqueda por código y ordenamiento por fecha, código o valor. El administrador puede crear un bono individual indicando código, monto, fecha de expiración y documento del cliente; el sistema busca el cliente por documento en tiempo real y muestra su nombre antes de guardar. El sistema exige código y documento no vacíos, monto numérico no negativo y fecha de expiración válida; si el documento no corresponde a exactamente un cliente producto existente, el sistema rechaza la creación. El administrador puede importar bonos de forma masiva desde un archivo CSV con las columnas `codigo, monto, fecha_expiracion, documento`, cargado por lotes; el sistema reporta filas procesadas, bonos creados, duplicados omitidos e inválidos omitidos. El administrador puede abrir el detalle de un bono y ver su código, estado (asignado o expirado), monto, valor utilizado, fecha de expiración, cliente vinculado y el historial de compras (origen admin o webhook). El administrador puede registrar manualmente una compra contra un bono desde su detalle, indicando el monto. |
| **Relaciones** | Casos de uso: [CU-031](../../Casos%20de%20Uso/6.%20Operaci%C3%B3n%20Admin/CU-031%20Ver%20y%20asignar%20bonos%20D1%20a%20clientes.md). | **Comentarios** | **Historia nueva, implementada.** No existía ninguna historia que documentara la pantalla "Bonos D1" del panel admin (visible en el menú lateral, sección "Producto"), a pesar de que el flujo completo (listar, crear, importar por CSV, ver detalle y registrar compras) ya está implementado. Se documenta a partir de la revisión de código de `apps/admin/src/app/product/bonos-d1` y del backend `backends/b2b`. **Hallazgo técnico crítico:** a diferencia de la mayoría de rutas del panel admin, las rutas de cupones en `backends/b2b/src/routes.ts` (`GET /coupons`, `POST /coupons`, `POST /coupons/import`, `POST /coupons/:id/purchases`, `GET /coupons/:id`) **no tienen ningún middleware de autenticación** (`authenticate`) ni de permisos aplicado; solo hay un middleware de logging a nivel de router. Esto significa que, en el estado actual del código, cualquiera con acceso de red al backend `b2b` podría listar, crear o importar bonos D1 sin sesión de administrador. Se recomienda con urgencia agregar autenticación y control de permisos a estas rutas antes de considerar el módulo listo para producción. **Pendiente de confirmar con negocio:** el criterio exacto para autorizar la asignación de un bono a un cliente (hoy el sistema no valida cupo, antigüedad ni ningún otro criterio de negocio más allá de que el documento corresponda a un único cliente producto existente). |
