#### HU-049: Configurar parámetros del sistema (cortes, tasas y reglas de crédito)

| Campo | Detalle |
|:---:|:---:|
| **Actor** | Administrador con permiso de edición de configuración (rol Sys Admin o Core Admin con el permiso "Editar configuración"); cualquier administrador autenticado puede consultar los parámetros en modo solo lectura. |
| **Historia** | Como administrador con permiso de edición de configuración, quiero consultar y editar los parámetros generales del sistema (fechas de corte, tasa de interés diaria, tasa de mora, plan de pagos y cargos aplicables), para poder ajustar las reglas del negocio sin necesidad de un despliegue de código. |
| **Prioridad** | Alta |
| **Criterios de aceptación** | Cualquier administrador con sesión activa puede listar los settings del sistema, cada uno identificado por un nombre único (`cutoff_dates`, `daily_interest_rate`, `overdue_interest_rate`, `payment_plan_config`, `payment_charges`, entre otros), con su descripción, su valor en formato JSON y la fecha de última actualización. Solo un administrador con el permiso "Editar configuración" puede modificar el valor de un setting; si no lo tiene, el campo de valor se muestra en modo solo lectura y el botón de guardar permanece deshabilitado. Al guardar, el sistema valida que el texto ingresado sea JSON válido antes de enviarlo; si no lo es, rechaza el guardado localmente sin llamar al backend. El sistema valida que el nombre del setting exista; si no existe, rechaza la actualización. Toda actualización exitosa o fallida queda registrada en el log de auditoría del panel. |
| **Relaciones** | Casos de uso: [CU-030](../../Casos%20de%20Uso/6.%20Operaci%C3%B3n%20Admin/CU-030%20Configurar%20parametros%20del%20sistema.md). Historias relacionadas: [HU-033](../5.%20Operaci%C3%B3n%20admin/HU-033%20Simular%20plan%20de%20pago%20con%20distintas%20tasas.md) (la simulación de plan de pago usa estos mismos parámetros como base). |

| **Comentarios** | **Historia nueva, implementada.** No existía ninguna historia que documentara la pantalla "Configuración" del panel admin, a pesar de que el código ya soporta la edición en vivo de parámetros críticos de negocio (fechas de corte, tasa de interés diaria, tasa de mora, plan de pagos y cargos). Se documenta a partir de la revisión de código realizada sobre `apps/admin/src/app/settings` y `backends/admin`. **Hallazgo técnico:** la ruta `PUT /settings/:name` solo exige `authenticate` en el backend; no aplica ningún middleware de permisos (a diferencia de otras rutas de mutación del panel). La restricción de edición por el permiso `core:update-setting` solo existe en el frontend (deshabilita el botón y el textarea). Esto significa que cualquier sesión autenticada con acceso directo a la API podría modificar parámetros financieros sensibles (tasa de interés, fechas de corte) sin pasar por la validación de permisos de la interfaz. Se recomienda agregar la verificación de permiso también en el backend. **Hallazgo adicional:** el tipo `THRESHOLD_DAYS_SETTING_NAME` (`threshold_days`) está declarado en `settings.types.ts` pero no se siembra ni se usa como setting independiente; el valor `thresholdDays` que sí está activo vive anidado dentro del setting `cutoff_dates`. |
