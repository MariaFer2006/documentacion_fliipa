# HU-046: Manejo de rechazo en biometría

| Campo | Detalle |
|:---:|:---|
| **Actor** | Sistema (Fliipa) / Cliente empresarial |
| **Historia** | Como sistema Fliipa, quiero gestionar el rechazo de una validación biométrica, ya sea como resultado automático o como resultado de una revisión manual por parte del analista de riesgo, para finalizar correctamente la solicitud cuando corresponda, notificar al cliente y mantener la trazabilidad del resultado. |
| **Prioridad** | Media |
| **Criterios de aceptación** | Cuando el sistema reciba un resultado de biometría con estado **“rechazado”**, debe registrar el resultado y ejecutar el flujo de rechazo definido para la solicitud. Cuando un caso se encuentre **“en revisión”** y el analista de riesgo confirme el rechazo, el sistema debe registrar la decisión y continuar con el flujo de rechazo correspondiente. Una solicitud que quede en estado de rechazo definitivo no debe permitir continuar con las siguientes etapas del onboarding. El sistema debe notificar al cliente el resultado de la solicitud mediante los canales de comunicación definidos para el proceso, sin exponer información técnica ni información sensible del proceso de validación. El motivo o causal del rechazo debe quedar registrado internamente para efectos de soporte, seguimiento y trazabilidad. |
| **Relaciones** | Casos de uso: CU-027. Historias relacionadas: HU-006, HU-022. |
| **Referencias** | Procesos — 01 Onboarding Digital, pasos 14 y 15 (Gestión del resultado biométrico / Revisión manual por analista de riesgo). En el repositorio `credits-platform-main` no se identificó lógica de biometría, integración con Olimpia ni una implementación específica para la notificación de rechazo biométrico. |

| **Comentarios** | **Historia nueva:** se documenta el manejo del rechazo biométrico como una historia independiente de HU-022, que corresponde a la revisión manual de casos en estado **“en revisión”**. La historia contempla tanto el resultado automático de la validación biométrica como el rechazo confirmado por el analista de riesgo. **Pendiente de confirmación con el dueño del proceso:** definir si un resultado automático **“rechazado”** de Olimpia constituye directamente un rechazo definitivo o si debe pasar previamente por revisión manual. Hasta confirmar esta regla de negocio, la historia no debe establecer uno de los dos comportamientos como obligatorio. La integración con Olimpia y la lógica de rechazo biométrico no se encuentran implementadas en el repositorio revisado. |
